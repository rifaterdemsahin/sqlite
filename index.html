Core Specification: What SQLite Is, What It Excels At & What It Is Not For

View Full Architecture Page →
📦 What SQLite Is
  • 📦
    In-Process Library Engine: A complete SQL database engine that runs inside your program as a library. There is no server process, no port, no password, and no network.
  • 📄
    Single Ordinary File: The whole database is one ordinary file (ai_workflow_sandbox.db). Copying the file copies the database.
  • 🐍
    Built into Python: Python ships it as the standard-library module sqlite3. Version on this Mac: 3.54.1.
  • 🧾
    ACID Transactions: Transactions are Atomic, Consistent, Isolated, and Durable, so a crash mid-write leaves the file consistent.
  • 🌍
    Public Domain & Ubiquitous: It is public domain and one of the most widely deployed databases in the world (phones, browsers, desktop & AI apps).
✅ What It Is Good At
  • ✅
    Local App State, Caches & Indexes: Ideal for local application state, prompt/embedding caches, secondary indexes, and small-to-medium datasets (up to many GB).
  • ✅
    Fast Reads with Real SQL: Zero IPC overhead enables microsecond reads with full relational power: GROUP BY, B-tree indexes, and ON CONFLICT upserts.
  • ✅
    Zero Setup & Zero Running Cost: No Docker containers to provision, no credentials to rotate, and $0 idle cloud database cost.
⚠️ What It Is Not For
  • ⚠️
    Many Simultaneous Writers: Only one write happens at a time for the whole file. High-throughput concurrent writers contend on the file lock.
  • ⚠️
    Access Over a Network Share: Putting the file on NFS/SMB or a cloud sync tool (Dropbox/iCloud) and opening it from several machines at once can corrupt it due to broken POSIX file locking.
  • ⚠️
    Multi-User Role-Based Access Control: There are no built-in GRANT/REVOKE user roles; anyone who can read/write the OS file owns the data.
